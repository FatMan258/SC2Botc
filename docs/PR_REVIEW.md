# Pull Request 审核与合并

这份指南用于维护者审核角色作者提交的 Pull Request。

## 1. 先看 PR 概览

- 阅读标题、说明和关联 Issue。
- 确认本次 PR 只处理一个角色或一个明确问题。
- 确认作者没有提交地图、Bank、账号信息或未授权素材。

## 2. 检查自动测试

PR 页面的 **Checks / 检查** 必须全部通过：

- Python 单元测试。
- 正式 Galaxy 脚本的编码、括号、函数重复和前置声明检查。
- 正式版与测试版地图构建。
- 构建产物回读。

测试失败时不要合并，先让作者修复。

## 3. 审核文件差异

在 **Files changed / 文件变更** 中检查：

- 新增角色是否有 `roles/` 规格。
- 角色文本、token、夜序和能力代码是否一致。
- 是否覆盖死亡、中毒、醉酒、换位和第二局清理。
- 是否误改无关角色或历史停用功能。

## 4. 处理评论

- **Comment**：提出问题，不阻止合并。
- **Request changes**：必须修改后才能合并。
- **Approve**：审核通过。

维护者可以自己提交 PR，但设置了强制第三方审核时，仍需要另一名审核者。

## 5. 合并方式

- **Squash and merge**：推荐用于角色投稿，把一个 PR 压缩成一个清晰提交。
- **Merge commit**：保留分支中的全部提交，适合较大的多人协作。
- **Rebase and merge**：要求每条提交都独立、干净。

合并前再次确认目标分支是 `main`，且 Checks 全部通过。

## 6. 合并之后

1. 在 PR 页面点击 **Delete branch** 删除远程功能分支。
2. 在本地切回 `main` 并更新：

   ```powershell
   git switch main
   git pull
   ```

3. 需要发布地图时，再从更新后的 `main` 构建正式产物。
